# 生产安全与密钥管理

## 1. 密钥放在哪里

| 文件 | 用途 | 是否提交 Git |
| --- | --- | --- |
| `deploy/production/.env` | Docker 的 MySQL、MinIO 密码 | 否 |
| `/etc/hm-badminton/app.env` | Spring Boot、地图、AI、邮件密钥 | 否 |
| `.env.example` / `app.env.example` | 变量名和占位值 | 是 |
| `application.yml` | 开发默认值和变量引用 | 是，但不能放生产密钥 |

服务器文件应执行：

```bash
chmod 600 /opt/hm-badminton/deploy/production/.env
chmod 600 /etc/hm-badminton/app.env
```

## 2. 必须轮换的凭据

若凭据曾出现在聊天截图、Git 提交、终端历史或前端代码中，应视为已泄露并重新生成：

- 高德 Web 服务 Key。
- 高德 JS Key。它本来会出现在浏览器中，因此必须配置 Web 域名白名单和调用范围。
- DashScope API Key。
- QQ 邮箱 SMTP 授权码。
- MySQL Root 密码。
- MinIO 管理账号和密码。
- Token/JWT 随机密钥。

生成随机值示例：

```bash
openssl rand -base64 48
```

轮换后要同时更新服务端环境文件并重启对应服务，旧凭据应立即禁用。

源码不再提供真实高德 Key 默认值：后端使用 `AMAP_KEY`，前端构建使用 `VITE_AMAP_JS_KEY`。生产 Profile 对 MySQL、MinIO、地图和 JWT 密钥采用 fail-fast，变量缺失时启动失败，这是预期的安全保护。

## 3. Git 检查

```bash
git status --short
git ls-files | grep -E '(^|/)(\.env|app\.env)$'
git grep -n -Ei '(api.?key|password|secret|authorization)'
```

如果真实密钥已经提交，删除当前文件还不够。应先在服务商控制台轮换，再考虑使用 `git filter-repo` 清理历史。重写公共仓库历史会影响协作者，执行前应备份并通知。

## 4. 网络边界

阿里云安全组只开放：

- `80/443`：网站访问。
- `22`：仅允许管理员固定公网 IP。

禁止向公网开放：`3307`、`6379`、`9876`、`10909-10912`、`9000`、`9001`、`8088`。这些端口在 Compose 和 Spring Boot 中也应绑定 `127.0.0.1`，形成安全组与主机监听双重限制。

## 5. 文件安全边界

当前 `hm-badminton` Bucket 配置为匿名下载，公开头像和博客图片可经 `/objects/` 读取。不要上传身份证、合同、通讯录或其他隐私文件。

真实业务应拆分：

- `hm-badminton-public`：头像、公开博客图，允许只读。
- `hm-badminton-private`：私密附件，禁止匿名访问，只能由后端鉴权后签发短期 URL。

上传还应增加文件头识别、图片解码验证、恶意文件扫描和图片重新编码。

## 6. 应用安全检查

- 登录 Token 只放请求头，不写日志、不拼进 URL。
- 验证码、密码和邮件授权码不得出现在异常信息中。
- 所有写接口由登录校验与资源所有权校验共同保护。
- 订单价格、库存、活动人数必须以后端查询为准，不能信任前端字段。
- Nginx 对 `index.html` 禁止缓存，对 Vite 哈希资源长期缓存。
- 证书续期失败应告警，不能等浏览器提示“不安全”后再处理。
