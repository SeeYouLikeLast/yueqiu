 球动球类生活服务项目规划

> 版本：v0.2  
> 日期：2026-06-28  
> 定位：仿照黑马点评 HMDP 的学习路径，做一个面向羽毛球、乒乓球、足球、篮球、网球、排球等球类运动的高并发生活服务项目。AI 应用层作为后续独立阶段接入。

## 1. 项目目标

项目名称暂定为 **球动 / ShuttleMate**。它不再是单一羽毛球平台，而是围绕“找场所、买装备、找球搭子、发起活动”做成通用球类生活服务应用：

- 场所：接入高德 Web 服务 POI 周边搜索，按运动类型实时搜索附近球馆、球场、训练中心，不再在首页展示虚构场馆数据。
- 场所交易：围绕真实 POI 维护平台自己的售卖项目，例如单人畅打、单场时段、私教课和核销订单。
- 装备：按运动类型展示球拍、球鞋、球、护具等装备，支持购物车、下单、模拟支付、高并发秒杀。
- 球友：按运动类型、城市、距离、时间、水平查找附近球友。
- 活动：支持选择真实高德 POI 作为活动地点，按人数、水平、时间组织同城约球。
- AI：后续接入自然语言搜索、计划生成、装备推荐、场所推荐和约球草稿生成。

第一阶段采用 **单体模块化 + 前后端分离**。核心链路跑通后，再拆分微服务、消息队列、搜索服务和 AI 服务。

## 2. 当前已落地范围

### 2.1 用户与认证

- 手机号 / 邮箱 / 用户名注册登录。
- JWT 登录态。
- 注册唯一性校验：
  - 先查 Redis 布隆过滤器。
  - 判断不存在时跳过数据库预查，直接尝试写库。
  - 判断可能存在时再查 MySQL 精确确认。
  - 写库成功后把唯一字段写入布隆过滤器。
  - MySQL 唯一索引作为最终兜底。

这个方案可行，因为布隆过滤器不会误判“不存在”，只可能误判“存在”；命中后再查数据库，可以兼顾性能和正确性。

### 2.2 球类运动目录

第一版内置运动类型：

| code | 名称 | 高德搜索关键词 |
| --- | --- | --- |
| badminton | 羽毛球 | 羽毛球馆、羽毛球场、羽毛球 |
| table_tennis | 乒乓球 | 乒乓球馆、乒乓球室、乒乓球 |
| football | 足球 | 足球场、足球俱乐部、足球 |
| basketball | 篮球 | 篮球馆、篮球场、篮球 |

| volleyball | 排球 | 排球馆、排球场、排球 |

后端接口：

```text
GET /api/sports
```

### 2.3 附近场所

首页附近场所从高德实时搜索：

```text
GET /api/places/nearby
```

请求参数：

```text
sport   运动类型，默认 badminton
city    城市
lng     经度
lat     纬度
radius  搜索半径，默认 5000 米
keyword 用户关键词，可为空
page    页码
size    每页数量
```

后端内部调用高德：

```text
GET https://restapi.amap.com/v5/place/around
```

核心参数：

```text
key
location
radius
keywords
region
page_size
page_num
show_fields=business,photos
```

约定：

- 未配置高德 Key 时接口直接返回错误，不使用本地虚构场馆兜底。
- 高德 POI 只作为实时场所来源；本地 `venues` 表保留给评价、收藏、后台管理和历史元数据。
- 约球活动可以保存高德 `place_id`、`place_source`、`venue_name`，不要求先把 POI 写入本地场馆表。

### 2.4 场所售卖与订场

高德提供真实场所，平台自己维护售卖项目和库存：

```text
TIME_PACKAGE   单人畅打，例如 08:00-12:00 单人畅打
COURT_SLOT     单场时段，例如 20:00-21:00 A1 标准场
COACH_LESSON   私教课，例如 私教体验课 60 分钟
```

核心接口：

```text
GET  /api/venue-products?sport=badminton&placeRank=1
GET  /api/venue-products/{id}/inventories
POST /api/venue/orders
POST /api/venue/orders/{id}/pay
GET  /api/venue/orders
```

售卖项目名称暂定为 **场馆团购**。附近场所由高德实时返回，平台售卖模板不再写死某个高德店名，而是用 `place_rank` 绑定“当前附近列表第 N 个场所”。下单时再把真实 `amapPlaceId`、真实场所名写入订单。

库存扣减采用数据库条件更新兜底：

```sql
update venue_product_inventory
set available_stock = available_stock - 1,
    sold_stock = sold_stock + 1
where id = ?
  and product_id = ?
  and status = '可售'
  and available_stock > 0
```

后续热门时段可以升级为 Redis Lua 预扣库存 + MQ 异步下单。

### 2.5 装备商城

装备数据按 `sport_code` 分类：

```text
GET /api/equipment/categories?sport=badminton
GET /api/equipment/products?sport=badminton
```

当前能力：

- 分类、商品列表、商品详情。
- 购物车。
- 普通下单、模拟支付。
- 商品库存扣减。
- 后台新增商品。

### 2.6 装备秒杀

秒杀链路：

```text
请求进入
 -> 校验登录和活动状态
 -> Redis Lua 原子判断库存和一人一单
 -> 创建 MySQL 秒杀订单
 -> 扣减数据库库存
```

兜底策略：

- Redis 不可用时降级到数据库条件扣减。
- MySQL 唯一索引 `uk_seckill_user_activity` 防止同一用户重复抢同一活动。
- 已接入 RocketMQ，把订单创建改成异步落库。

### 2.7 附近球友与同城约球

球友资料按 `sport_code` 过滤：

```text
GET /api/social/players?sport=badminton&lng=108.946465&lat=34.347269
X-Location-City: 西安
```

活动按 `sport_code` 过滤：

```text
GET /api/social/activities?sport=badminton
X-Location-City: 西安
POST /api/social/activities
```

活动字段支持：

```text
sportCode
placeSource
placeId
venueName
city
startTime
endTime
maxPlayers
levelRequired
feeType
```

## 3. 技术栈

当前实现：

- 后端：Java 21、Spring Boot 3.5、MyBatis-Plus、Spring Data Redis、Redisson、RocketMQ Spring、MinIO SDK。
- 数据：MySQL 8.4、Redis 7.4、RocketMQ、MinIO。
- 地图：高德 Web 服务 API，POI 周边搜索。
- 前端：Vue 3、TypeScript、Vite、lucide-vue-next。
- 部署：Docker Compose 管理 MySQL / Redis / MinIO。

后续增强：

- MyBatis-Plus：统一替换旧 JDBC 访问，Mapper + Service 接口分层。
- RocketMQ：秒杀异步下单、通知、活动消息。
- Elasticsearch / OpenSearch：商品、评价、活动、场所元数据搜索。
- Spring AI：AI 应用层。
- SSE / WebSocket：AI 流式输出、活动聊天室、秒杀结果推送。

## 6. 高并发重点

### 6.1 注册唯一性

```text
标准化唯一字段
 -> 查询布隆过滤器
 -> 不存在：跳过数据库预查
 -> 可能存在：查数据库确认
 -> 写入 MySQL
 -> 写入布隆过滤器
 -> 唯一索引兜底
```

### 6.2 场所搜索

当前首页使用高德实时搜索，不缓存虚构场馆。

后续优化：

- 热门关键词和城市可短 TTL 缓存高德结果。
- 缓存 Key 包含 `sport + city + lng/lat 网格 + radius + keyword`。
- 遵守高德 API 配额，不对实时 POI 做无限制高频穿透。
- 用户评价、收藏、活动绑定本地元数据，避免污染 POI 源数据。

### 6.3 秒杀

- Redis Lua 保证库存扣减和一人一单的原子性。
- MySQL 唯一索引兜底。
- Redis 异常时数据库降级。
- 使用 RocketMQ 做异步落库；Redis 预扣成功但消息发送失败时回滚 Redis 预扣，数据库唯一索引兜底一人一单。

### 6.4 附近球友

- MySQL 保存长期城市、区域、水平、运动类型。
- 经纬度用于距离排序。
- 后续可使用 Redis GEO 保存短期活跃位置。
- 位置展示要做隐私保护，避免精确暴露住址。

## 7. 启动配置重点

高德 Key：

```yaml
hm:
  amap:
    key: ${AMAP_KEY:}
```

Windows PowerShell 临时配置：

```powershell
$env:AMAP_KEY="你的高德Web服务Key"
mvn spring-boot:run
```

WSL / Linux 临时配置：

```bash
export AMAP_KEY="你的高德Web服务Key"
mvn spring-boot:run
```
