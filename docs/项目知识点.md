## 知识点 1：项目使用的专业工具与技术栈

### 1.1 四个核心组件的分工

| 组件 | 在本项目中的职责 |
| --- | --- |
| Spring Boot | 提供后端接口，组织业务逻辑，管理事务，并连接数据库和各种中间件 |
| Vue | 负责用户看到的移动端页面、状态展示和点击交互 |
| Vite | 在开发阶段启动前端、热更新源码、代理接口，并在发布前构建静态文件 |
| Nginx | 在生产环境提供静态前端、HTTPS、反向代理和图片缓存 |

它们并不是互相替代的关系，而是分别位于不同阶段：

```text
开发阶段：浏览器 -> Vite -> Spring Boot
生产阶段：浏览器 -> Nginx -> Spring Boot
```

### 1.2 项目的完整技术链路

```text
浏览器
  └─ Vue 3 + TypeScript + Fetch + Lucide
       ├─ 开发入口：Vite :5173
       └─ 生产入口：Nginx :80/:443
             │
             ▼
        Spring Boot :8088
          ├─ MyBatis-Plus + HikariCP -> MySQL
          ├─ Spring Data Redis + Lettuce -> Redis
          ├─ Redisson + Lua -> 分布式并发控制
          ├─ RocketMQ -> 秒杀订单异步落库
          ├─ MinIO SDK -> MinIO 对象存储
          ├─ Spring AI Alibaba -> DashScope/通义千问
          ├─ RestClient -> 高德 Web 服务 API
          └─ JavaMailSender -> QQ 邮箱 SMTP
```

### 1.7 RocketMQ 消息队列

RocketMQ 用于把秒杀接口和数据库订单创建解耦：

```text
秒杀请求
  -> Redis Lua 原子预扣
  -> 发送 RocketMQ 消息
  -> 消费者异步创建 MySQL 订单
```

它的价值是降低秒杀请求耗时并削平瞬时流量。消费者通过订单号、数据库唯一索引和幂等判断避免重复消息创建重复订单。

在低内存 ECS 的 `lite` 模式下 RocketMQ 可以不启动，项目会根据配置使用同步事务落库作为降级方案。

### 1.8 MinIO 对象存储

MinIO 保存头像、博客图片和装备图片等文件本体，MySQL 只保存文件元数据和对象键：

```text
MySQL：文件 id、所有者、对象键、MIME、大小
MinIO：真正的 jpg、png、webp 等文件内容
```

生产环境使用 Nginx 的 `/objects/` 路径直接代理 MinIO，因此图片不需要每次经过 Spring Boot。MinIO SDK 负责上传、删除和对象管理。

## 知识点 2：Vite、Nginx、HTTPS 与反向代理
| 对比项    | 开发环境 Vite      | 生产环境 Nginx    |
| ------ | -------------- | ------------- |
| 使用阶段   | 开发、调试          | 正式部署          |
| 常见端口   | 5173           | 80、443        |
| 是否编译源码 | 会即时编译          | 不编译源码         |
| 提供的内容  | 开发中的源码和模块      | 构建后的静态文件      |
| 热更新    | 支持             | 不支持           |
| HTTPS  | 可配置，但通常不作为正式入口 | 常用于配置正式 HTTPS |
| 接口代理   | 开发代理           | 生产反向代理        |
| 性能目标   | 开发效率           | 稳定性和访问性能      |
| 是否适合公网 | 不推荐            | 适合            |
| 启动方式   | `npm run dev`  | 启动 Nginx 服务   |
| 前端修改后  | 自动热更新          | 需要重新构建并部署     |

### 2.1 Nginx 在项目中的职责

生产环境中的 Nginx 是浏览器访问整个系统的统一入口，主要负责：

1. 监听公网的 HTTP `80` 和 HTTPS `443` 端口。
2. 将 HTTP 请求重定向到 HTTPS。
3. 直接返回 Vue 构建后的静态文件。
4. 将 `/api/` 请求反向代理到 Spring Boot。
5. 将 `/objects/` 请求反向代理到 MinIO。
6. 为图片设置浏览器缓存和 Nginx 代理缓存。
7. 隐藏 `8088`、`9000` 等内部端口，减少公网攻击面。

项目中的生产配置模板是：

- [`deploy/production/nginx/hm-badminton.conf`](../deploy/production/nginx/hm-badminton.conf)

部署到 ECS 后，真正被 Nginx 读取的文件通常是：

```text
/etc/nginx/conf.d/hm-badminton.conf
```

### 2.2 外部 HTTPS 与内部 HTTP

项目的完整请求链路是：

```text
浏览器
  │ HTTPS :443
  ▼
Nginx（TLS 终止、静态文件、反向代理）
  ├─ HTTP 127.0.0.1:8088 ──> Spring Boot
  └─ HTTP 127.0.0.1:9000 ──> MinIO
```

浏览器与 Nginx 之间使用 HTTPS，数据经过公网时会被 TLS 加密。Nginx 收到请求后完成解密，再通过本机回环地址 `127.0.0.1` 请求 Spring Boot 或 MinIO。

因此，下面的配置并不代表用户正在使用 HTTP：

```nginx
proxy_pass http://127.0.0.1:8088;
proxy_pass http://127.0.0.1:9000/;
```

它们只表示 Nginx 与同一台服务器上的内部服务使用 HTTP 通信。`127.0.0.1` 流量不会经过公网，通常没有必要再为这一段配置 HTTPS。

### 2.3 80 端口如何跳转到 443

HTTP 服务块监听 `80`：

```nginx
server {
    listen 80;
    server_name your-domain.example;

    location / {
        return 301 https://$host$request_uri;
    }
}
```

这不是把一个已经建立的 HTTP 连接直接变成 HTTPS，而是返回 `301` 重定向：

```text
1. 浏览器请求 http://example.com/path
2. Nginx 返回 Location: https://example.com/path
3. 浏览器重新连接 example.com:443
4. 浏览器与 Nginx 完成 TLS 握手
5. 浏览器发送加密后的 HTTPS 请求
```

因此，Nginx 必须同时保留 `80` 和 `443` 两个监听服务。`80` 还可用于 Let's Encrypt 的 ACME 证书校验。

### 2.4 443 服务块与证书

```nginx
server {
    listen 443 ssl;
    server_name your-domain.example;

    ssl_certificate /etc/letsencrypt/live/your-domain.example/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.example/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
}
```

各配置的含义：

| 配置 | 含义 |
| --- | --- |
| `listen 443 ssl` | 在 443 端口接收 HTTPS 请求 |
| `server_name` | 当前服务块处理的域名或公网 IP |
| `ssl_certificate` | 服务器证书和证书链 |
| `ssl_certificate_key` | 与证书匹配的私钥，不能公开 |
| `ssl_protocols` | 仅允许较安全的 TLS 1.2 和 TLS 1.3 |

仓库中的 `your-domain.example` 是占位值，部署时必须替换成真实域名或证书对应的公网 IP。

### 2.5 Vue 静态文件与单页路由

```nginx
root /var/www/hm-badminton;
index index.html;

location / {
    try_files $uri $uri/ /index.html;
}
```

前端执行 `npm run build` 后生成 `frontend/dist`，部署时将其中的文件同步到：

```text
/var/www/hm-badminton
```

`try_files` 会先查找真实文件。当用户访问 `/assistant` 等前端路由且磁盘中没有同名文件时，Nginx 返回 `index.html`，再由 Vue 决定展示哪个页面。没有这个回退时，刷新前端子页面通常会得到 Nginx `404`。

### 2.6 `/api/` 如何转发到 Spring Boot

```nginx
location /api/ {
    rewrite ^/api/?(.*)$ /$1 break;
    proxy_pass http://127.0.0.1:8088;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

请求转换示例：

```text
浏览器请求：https://example.com/api/agent/chat
删除前缀后：/agent/chat
内部请求：http://127.0.0.1:8088/agent/chat
```

相关请求头的作用：

| 请求头 | 作用 |
| --- | --- |
| `Host` | 告诉后端用户访问的主机名 |
| `X-Real-IP` | 将浏览器客户端 IP 传给后端 |
| `X-Forwarded-For` | 记录代理链上的客户端地址 |
| `X-Forwarded-Proto` | 告诉后端原始协议是 `https` |

浏览器只能看到 `https://example.com/api/...`，不会直接访问或看到服务器内部的 `127.0.0.1:8088`。

### 2.7 `/objects/` 如何转发到 MinIO

```nginx
location /objects/ {
    proxy_pass http://127.0.0.1:9000/;
}
```

例如：

```text
外部地址：https://example.com/objects/hm-badminton/blog/a.webp
内部地址：http://127.0.0.1:9000/hm-badminton/blog/a.webp
```

这样可以让浏览器通过 HTTPS 读取图片，同时无需将 MinIO 的 `9000`、`9001` 端口开放到公网。

配置中的缓存指令表示：

```nginx
proxy_cache hm_media;
proxy_cache_lock on;
proxy_cache_valid 200 30d;
add_header Cache-Control "public, max-age=2592000, immutable" always;
```

- 成功响应可在 Nginx 中缓存 30 天。
- 同一个未缓存对象并发回源时只允许一个请求回源。
- 浏览器也可以缓存 30 天。
- `immutable` 适用于 URL 对应内容不会变化的文件；更新图片时应使用新的对象名或 URL。

### 2.8 本地开发为什么不使用生产 Nginx

执行 `npm run dev` 时，浏览器访问的是 Vite 开发服务器。代理规则在：

- [`frontend/vite.config.ts`](../frontend/vite.config.ts)

```text
/api     -> http://localhost:8088
/objects -> http://localhost:9000
```

本地开发与生产环境的区别：

| 环境          | 前端服务           | API 转发者    | 配置文件                                        |
| ----------- | -------------- | ---------- | ------------------------------------------- |
| 本地开发        | Vite `5173`    | Vite proxy | `frontend/vite.config.ts`                   |
| 本地 Nginx 容器 | Nginx `80`     | Nginx      | `deploy/nginx/default.conf`                 |
| ECS 生产环境    | Nginx `80/443` | Nginx      | `deploy/production/nginx/hm-badminton.conf` |

前端代码始终请求相对地址 `/api` 和 `/objects`，所以不需要知道后端真实端口，环境切换时也不需要修改业务代码。

### 2.9 端口和安全组

生产服务器建议只对公网开放：

```text
80   HTTP 重定向和证书校验
443  HTTPS 正式访问
22   SSH，仅允许可信来源 IP
```

以下端口只绑定 `127.0.0.1`，不应加入公网安全组：

```text
8088       Spring Boot
9000/9001  MinIO API/控制台
3307       MySQL
6379       Redis
9876       RocketMQ NameServer
10909-10912 RocketMQ Broker
```

### 2.10 修改配置后的验证步骤

在 ECS 上修改 Nginx 配置后执行：

```bash
# 检查语法，不会直接重启服务
sudo nginx -t

# 平滑加载新配置，已有连接不会被强制中断
sudo systemctl reload nginx

# 查看 Nginx 最终合并后的全部生效配置
sudo nginx -T

# 查看服务状态和近期错误
sudo systemctl status nginx
sudo journalctl -u nginx -n 100 --no-pager
```

检查请求链路：

```bash
curl -I http://你的域名
curl -I https://你的域名
curl -I https://你的域名/api/sports
curl -I https://你的域名/objects/hm-badminton/某个对象
```

预期结果：HTTP 返回 `301`，HTTPS 首页正常，`/api` 由后端响应，`/objects` 由 MinIO 响应。

### 2.11 常见误区

1. `proxy_pass http://127.0.0.1` 不代表网站没有 HTTPS，它只是服务器内部连接。
2. `listen 80` 不会自动提供 HTTPS，必须由浏览器按照 `301` 地址重新访问 `443`。
3. 仓库里的配置只是模板，ECS 实际生效的是 `/etc/nginx/` 下的配置。
4. 修改仓库文件不会自动修改服务器配置，部署后还需要复制并 `reload nginx`。
5. `frontend/dist` 是构建结果，不是 Nginx 配置文件。
6. HTTPS 证书中的主机名必须和用户访问的域名或公网 IP 对应。
7. `nginx -t` 成功只代表语法正确，不代表后端、MinIO 或证书一定可用。
