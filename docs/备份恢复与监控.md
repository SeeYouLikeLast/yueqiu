# 备份、恢复与监控

## 1. 数据优先级

1. MySQL：用户、订单、库存、博客、活动、文件元数据，是最终事实，必须备份。
2. MinIO：头像和用户博客图片，必须与 MySQL 元数据配套备份。
3. 生产配置：`.env`、`app.env`、Nginx、systemd 和证书配置，必须加密备份。
4. Redis：Token、缓存、验证码、Feed 和临时 AI 会话，可重建；通常不作为灾备恢复的第一优先级。
5. RocketMQ：秒杀在途消息。恢复时应结合订单号、唯一索引和日志核对，不直接把它当订单事实库。

## 2. MySQL 备份

在 ECS 上执行：

```bash
cd /opt/hm-badminton/deploy/production
mkdir -p /var/backups/hm-badminton/mysql
docker compose --env-file .env exec -T mysql \
  sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers hm_badminton' \
  | gzip > /var/backups/hm-badminton/mysql/hm_badminton-$(date +%F-%H%M%S).sql.gz
```

备份后至少检查文件非空，并将副本同步到 ECS 之外的存储。只放在同一块云盘上不能抵御主机或磁盘损坏。

恢复前先停止后端写入并再次备份现状：

```bash
systemctl stop hm-badminton
gunzip -c /path/to/backup.sql.gz | docker compose --env-file .env exec -T mysql \
  sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" hm_badminton'
systemctl start hm-badminton
```

恢复属于高风险操作，必须先在临时数据库演练并核对用户数、订单数和库存。

## 3. MinIO 备份

推荐在服务器安装 MinIO Client `mc`，然后镜像 Bucket：

```bash
mc alias set hm-local http://127.0.0.1:9000 MINIO_ROOT_USER MINIO_ROOT_PASSWORD
mc mirror --overwrite hm-local/hm-badminton /var/backups/hm-badminton/minio
```

备份目录还应同步到另一台服务器、OSS 或离线存储。恢复后需要抽查 `file_metadata.object_name` 对应对象是否存在。

## 4. 配置备份

需要备份但不得放入公共 Git：

```text
/etc/hm-badminton/app.env
/opt/hm-badminton/deploy/production/.env
/etc/nginx/conf.d/hm-badminton.conf
/etc/systemd/system/hm-badminton.service
/etc/letsencrypt/
```

配置备份必须加密并限制访问权限。

## 5. 最低监控项

| 组件 | 监控内容 |
| --- | --- |
| Nginx | 4xx/5xx、请求耗时、证书剩余时间 |
| Spring Boot | 进程存活、接口 P95/P99、异常率、JVM 内存、线程数 |
| MySQL | 连接数、慢 SQL、磁盘、锁等待、备份结果 |
| Redis | 内存、淘汰、命中率、连接数、Big Key |
| MinIO | 磁盘、对象错误、备份结果 |
| RocketMQ | Broker 存活、堆积、消费失败、重试 |
| AI/高德 | 调用耗时、超时率、限流率、费用、降级率 |

当前最低限度可以用 `systemd`、Docker Healthcheck、日志和阿里云监控；进一步应接入 Micrometer、Prometheus、Grafana 和告警渠道。

## 6. 日常检查命令

```bash
systemctl is-active nginx hm-badminton
systemctl status hm-badminton --no-pager
journalctl -u hm-badminton --since '30 minutes ago' --no-pager
cd /opt/hm-badminton/deploy/production
docker compose --env-file .env ps
docker stats --no-stream
df -h
free -h
systemctl status hm-badminton-certbot-renew.timer --no-pager
```

## 7. 建议的恢复目标

演示系统可以先采用：每日一次完整备份，保留 7 个日备份和 4 个周备份；RPO 不超过 24 小时，RTO 不超过 4 小时。真实收费业务需要更短目标、数据库增量日志和跨可用区灾备。
