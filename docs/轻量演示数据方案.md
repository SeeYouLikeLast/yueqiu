# 轻量演示数据方案

## 目标

本方案用于本地演示，不追求海量压测。核心目标是：

- 首页仍然通过高德 API 获取真实附近场所。
- 本地数据库只保存演示业务数据。
- 场馆商品、库存、教练、场馆号、评价等按搜索结果顺序槽位绑定，减少数据量。
- 图片不再使用外部图片链接，统一生成本地图片并上传到 MinIO。

## 场所绑定规则

演示版不把所有业务数据强绑定到真实 `amap_place_id`，而是使用：

```text
city + sport_code + place_rank
```

其中 `place_rank` 表示高德返回的第 N 个搜索结果。

示例：

```text
西安 + badminton + rank 1
```

表示“西安羽毛球搜索结果中的第 1 个场所”挂载的一组演示商品、教练、评价和场馆号。

用户真正下单时，订单仍然保存当前高德场所快照：

```text
amap_place_id
venue_name
venue_address
longitude
latitude
```

这样即使高德排序变化，历史订单也不会错位。

## 图片分区

脚本生成 120 张本地 PNG 图片：

| ID 范围 | 类型 | MinIO object 前缀 |
|---|---|---|
| 1-30 | 用户头像 | `demo/users/avatar/` |
| 31-55 | 场馆封面 | `demo/places/cover/` |
| 56-80 | 装备封面 | `demo/equipment/cover/` |
| 81-110 | 博客图片 | `demo/blogs/images/` |
| 111-120 | 评价图片 | `demo/reviews/images/` |

数据库中的图片地址统一使用：

```text
/api/files/{id}/download
```

## 执行方式

在项目根目录执行：

```powershell
.\scripts\seed-light-demo.ps1
```

如果只生成 SQL 和本地图片，不上传 MinIO：

```powershell
.\scripts\seed-light-demo.ps1 -SkipUpload
```

脚本会生成：

```text
backend/src/main/resources/db/data.sql
seed-assets/generated/
```

如果 `hm-badminton-minio` 容器正在运行，脚本会自动把 `seed-assets/generated/demo` 上传到 MinIO 的 `hm-badminton` bucket。

## 相关代码

- 数据生成脚本：`scripts/seed-light-demo.ps1`
- 初始化 SQL：`backend/src/main/resources/db/data.sql`
- 场馆号表：`backend/src/main/resources/db/schema.sql`
- 高德场所封面本地化：`AmapPlaceService.localPlaceCoverUrl`
- 前端兜底图：`FALLBACK_IMAGE`、`FALLBACK_AVATAR`

## 后续扩展

如果要从演示版升级到生产版，应逐步把这些数据从 `place_rank` 绑定迁移到 `amap_place_id` 强绑定：

- 场馆商品
- 驻场教练
- 场馆号
- 场馆评价
- 场馆公告
- 场馆优惠券

演示阶段保留 `place_rank` 可以显著减少数据准备成本。
