# 运动目录、附近场所与评价

## 1. 功能

- 返回平台支持的球类运动。
- 调用高德 Web 服务 API 搜索真实附近场所。
- 结果不足一页时由后端自动扩大搜索半径。
- 逆地理编码和 IP 定位兜底。
- 以“城市 + 运动 + 场所顺序”关联平台评价和场馆商品。

## 2. HTTP 接口

| 方法 | 路径 | 主要参数 | 作用 |
| --- | --- | --- | --- |
| GET | `/api/sports` | 无 | 运动目录 |
| GET | `/api/places/nearby` | `sport,keyword,lng,lat,radius,page,size` | 附近真实 POI |
| GET | `/api/places/regeo` | `lng,lat` | 坐标转地址 |
| GET | `/api/places/ip-location` | 无 | 客户端 IP 城市级兜底 |
| GET | `/api/venues/reviews/{sport}/{placeRank}` | `page,size` | 按场所槽位查评价 |

城市通过 `X-Location-City` 请求头、登录 token 或默认西安解析，避免在所有 URL 重复携带中文地址。

## 3. 附近场所查询链路

1. `PlaceController` 校验经纬度并解析城市。
2. `AmapPlaceService` 将运动 code 归一化为高德搜索关键词。
3. 经纬度保留 4 位小数构建 Redis Key，合并相邻刷新请求。
4. 未命中缓存时请求高德 `/v5/place/around`。
5. 数量不足时按策略扩大半径，以 POI id 去重后截断为一页。
6. 场所图片优先使用高德 `photos`，无图时由前端渲染本地占位图。

## 4. 场所与平台数据的关联

高德 POI 会随用户位置变化。演示数据采用 `placeRank`槽位：

```text
高德当前结果第 N 个场所
  -> city + sport + placeRank=N
  -> 评价、场馆商品、教练/场馆号扩展数据
```

这个方案适合轻量演示，可用少量平台数据适配不同地点。商业化时应改为场馆入驻后绑定稳定 `amap_place_id`。

## 5. 缓存

| Key | TTL | 作用 |
| --- | --- | --- |
| `catalog:sports` | 24 小时 | 运动目录 |
| `amap:nearby:*` | 2 分钟 + 抖动 | 附近 POI |
| `amap:regeo:*` | 30 分钟 | 逆地理编码 |
| `amap:ip:*` | 10 分钟 | IP 定位 |

## 6. 数据与代码入口

- MySQL：`place`、`venue_reviews`、`coaches`、`venue_operators`。
- 外部系统：高德 Web 服务 API。
- 代码：`SportController`、`PlaceController`、`VenueController`、`SportCatalogService`、`AmapPlaceService`、`VenueService`。

## 7. 失败降级

- 精确坐标缺失时不伪造“附近”结果。
- 高德 IP 定位失败时回退默认西安。
- 缓存只是减少外部调用，不把场所团购或评价伪装成高德数据。
