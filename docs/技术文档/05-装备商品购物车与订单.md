# 装备商品、购物车与订单

## 1. 功能

- 按运动、类别和关键词查询装备。
- 查看装备详情。
- 购物车加购、数量增减、删除和结算。
- 立即购买和购物车合单。
- 普通装备订单与秒杀装备订单统一展示。

`TradeType.EQUIPMENT = 2`。

## 2. HTTP 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/categories/2?sport=...` | 装备分类 |
| GET | `/api/items/2` | 装备分页查询 |
| GET | `/api/items/2/{id}` | 装备详情 |
| POST | `/api/cart` | `type=2` 加购 |
| GET | `/api/cart` | 统一购物车 |
| PATCH | `/api/cart/2/{itemId}` | 修改数量 |
| DELETE | `/api/cart/2/{itemId}` | 删除商品 |
| POST | `/api/payments` | 立即购买并支付 |
| POST | `/api/payments/cart` | 购物车结算并支付 |
| GET | `/api/orders/2` | 普通 + 秒杀装备订单 |

## 3. 列表与详情

`EquipmentService.items()` 使用 MyBatis-Plus 分页，运动、分类和关键词都在后端转成条件查询。列表不依赖位置，所以“按距离重新筛选装备”不会被错误转成场馆团购。

详情使用 `equipment:{id}` 短缓存和空值缓存，避免重复读和恶意请求不存在 id 造成缓存穿透。

## 4. 购物车

- `cart_equipment` 以 `user_id + equipment_id` 识别用户商品。
- 重复加购会更新数量，不在前端维护独立真相。
- 数量不小于 1；前端提供 `- / + / 删除`。
- 购物车页只在用户进入时查询，“我的”首页不为展示数量额外加载。

## 5. 订单事务

1. `EquipmentService.createOrder()` 判断来源是直接购买还是购物车。
2. 从 MySQL 重新读取商品价格、状态和库存。
3. 计算总金额并写入 `order_equipment`。
4. 逐项执行 `stock >= quantity` 条件扣库存。
5. 写入 `order_equipment_item` 商品快照，保证商品修改后历史订单不变。
6. 购物车来源在成功后清空对应项。
7. `TradeOrderService` 外层事务再将订单更新为已支付。

内层 `@Transactional` 可保证该 Service 方法被其他入口单独调用时仍然完整；由外层事务调用时会加入已存在的事务。

## 6. 库存和金额安全

- 价格、商品名、库存都从后端数据库读取。
- 前端不传总金额，也不能直接修改订单状态。
- 条件 UPDATE 保证并发扣减不会把库存变成负数。
- 本项目支付为演示流程，未包含真实支付签名、回调幂等和退款。

## 7. 数据与代码入口

- MySQL：`equipment_categories`、`equipment`、`cart_equipment`、`order_equipment`、`order_equipment_item`。
- Controller：`CategoryController`、`ItemController`、`CartController`、`PaymentController`、`OrderController`。
- Service：`EquipmentService`、`TradeOrderService`。
- Mapper：`EquipmentMapper`、`EquipmentOrderMapper`。
