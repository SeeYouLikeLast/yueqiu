# 球友资料与约球活动

## 1. 功能

- 维护球友名片：常打运动、水平、城市、区域、打法、可约时间和介绍。
- 按运动、城市、区域、水平和距离查找球友。
- 创建、查询和加入约球活动。
- 活动分为“自己发起 / 他人发起 / 自己加入”。
- 购买场馆时段后一次性创建同时段约球活动。

## 2. HTTP 接口

| 方法 | 路径 | 登录 | 作用 |
| --- | --- | --- | --- |
| GET | `/api/social/players` | 可选 | 附近球友分页 |
| GET | `/api/social/profile/me` | 是 | 自己球友资料 |
| POST | `/api/social/profile/me` | 是 | 保存球友资料 |
| GET | `/api/social/activities` | 可选 | 活动分页，`scope=created/joined/others` |
| POST | `/api/social/activities` | 是 | 发起约球 |
| POST | `/api/social/activities/{id}/join` | 是 | 加入活动 |
| POST | `/api/social/activities/book-and-create` | 是 | 购买场馆时段并发起活动 |

## 3. 球友查询

1. 城市从位置请求头/token/默认城市解析。
2. 已登录用户未显式传坐标时，使用 token 中经纬度。
3. Mapper 按运动和水平过滤，有坐标时计算距离。
4. `excludeUserId` 过滤当前用户，“同城搭子”不展示自己。
5. 结果使用 `social:players:*` 1 分钟短缓存。

## 4. 创建活动

`SocialService.createActivity()` 在事务中：

1. 归一化运动类型。
2. 校验开始时间未过期，结束时间晚于开始时间。
3. 校验计划人数和水平要求。
4. 写入 `sport_activities`。
5. 写入发起人到 `sport_activity_members`，当前人数从 1 开始。
6. 清理活动列表缓存。

## 5. 并发加入

1. 成员表唯一索引防止同一用户重复加入。
2. 先写成员关系。
3. 条件 UPDATE：`current_players < max_players AND status='招募中'`。
4. UPDATE 失败抛异常，`@Transactional` 回滚刚插入的成员，不留脏数据且不超员。

## 6. 购买后发起约球

`VenueActivityBookingService.bookAndCreateActivity()` 将两条链路放入同一 MySQL 事务：

1. 校验场馆库存日期/时段。
2. 创建并模拟支付场馆订单。
3. 以订单中的场馆、日期和时段创建活动。
4. 前端必须在写操作前二次确认人数和水平要求。

## 7. 演示活动时间维护

`ActivityMaintenanceService` 定时将演示活动移到今天/明天可用时段，并将真实过期用户活动标记结束。定时任务不在每次列表请求中重写数据。

## 8. 数据与代码入口

- MySQL：`player_profiles`、`sport_activities`、`sport_activity_members`。
- Service：`SocialService`、`VenueActivityBookingService`、`ActivityMaintenanceService`。
- Mapper：`SocialMapper`、`PlayerProfileMapper`。
- Controller：`SocialController`。
