# 场馆商品、库存、购物车与订单

## 1. 领域概念

- `place`：真实场所/POI。
- `venue`：平台销售的场馆商品，例如畅打套餐、单场 1 小时、私教课。
- `venue_inventory`：商品在某日期和时段的可售库存。
- `order_venue`：用户购买后的订单快照和核销码。

`TradeType.VENUE = 1`，与装备交易共用分类、商品、购物车、支付和订单入口。

## 2. HTTP 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/categories/1` | 场馆商品分类 |
| GET | `/api/items/1` | 场馆商品分页/场所绑定查询 |
| GET | `/api/items/1/{id}` | 商品详情 |
| GET | `/api/items/1/{id}/inventories` | 指定日期可售时段 |
| POST | `/api/cart` | `type=1` 加入场馆购物车 |
| GET | `/api/cart` | 场馆 + 装备统一购物车 |
| PATCH | `/api/cart/1/{itemId}` | 修改数量 |
| DELETE | `/api/cart/1/{itemId}` | 删除购物车项 |
| POST | `/api/payments` | `type=1` 立即购买并模拟支付 |
| POST | `/api/payments/cart` | 购物车结算 |
| GET | `/api/orders/1` | 普通 + 秒杀场馆订单 |

## 3. 查询策略

`GET /items/1` 支持两种模式：

1. 销售页：使用 `sport/category/keyword/page/size` 分页查询平台可售商品。
2. 场所详情：使用 `amapPlaceId/venueId/placeRank/limit` 只查当前场所团购，避免列表对每个场所发起请求。

## 4. 立即购买链路

1. 前端选择商品、日期和 `inventoryId`。
2. `TradeOrderService.payDirect()` 根据 `type=1` 路由到 `VenueItemService`。
3. `createOrder()` 读取真实库存，校验日期/时段可用性。
4. Mapper 使用 `available_stock > 0` 的条件 UPDATE 扣库存。
5. 写入 `order_venue`，保存商品名、场馆名、日期、时段、价格快照。
6. 模拟支付将订单更新为已支付并返回核销码。

“创建 + 支付”的外层方法使用 `@Transactional`，中间任何一步失败都回滚 MySQL 库存和订单。

## 5. 购物车结算

- `cart_venue` 保存选定的商品和库存时段。
- 结算时重新读取库存和价格，不信任前端传入金额。
- 成功后清理已结算购物车项。
- 场馆时段通常是独占资源，当前项目仍保留 quantity 统一契约，业务上应以 1 份为主。

## 6. 并发与安全

- 不向前端返回内部扣库 SQL 和系统并发细节。
- 最终库存以 MySQL 条件 UPDATE 为准，受影响行数为 0 即库存不足。
- 订单只能按当前 `userId` 查询和支付。
- 支付是演示状态流转，不是真实第三方支付。

## 7. 数据与代码入口

- MySQL：`venue`、`venue_inventory`、`cart_venue`、`order_venue`。
- Service：`VenueItemService`、`TradeOrderService`。
- Mapper：`VenueItemMapper`、`VenueOrderMapper`。
- Controller：`ItemController`、`CategoryController`、`CartController`、`PaymentController`、`OrderController`。
