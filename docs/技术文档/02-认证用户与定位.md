# 认证、用户与定位

## 1. 功能

- 邮箱验证码发送和限流。
- 验证码注册/登录与密码登录。
- 用户唯一性预检和 MySQL 唯一索引兜底。
- 当前用户资料、公开主页和位置更新。
- Redis token 登录态和滑动续期。

## 2. HTTP 接口

| 方法 | 路径 | 登录 | 作用 |
| --- | --- | --- | --- |
| POST | `/api/auth/code` | 否 | 发送邮箱验证码 |
| POST | `/api/auth/register` | 否 | 显式注册并返回 token |
| POST | `/api/auth/login` | 否 | 验证码或密码登录 |
| GET | `/api/auth/me` | 是 | 当前用户完整资料 |
| PUT | `/api/auth/me` | 是 | 修改个人资料 |
| GET | `/api/auth/users/{id}` | 可选 | 公开主页及关注状态 |
| PUT | `/api/auth/location` | 是 | 更新城市、坐标和精确地址 |

## 3. 验证码链路

1. Validation 校验邮箱格式。
2. `login:code:email:cooldown:{email}` 保证同一邮箱 60 秒内不重复发送。
3. `login:code:email:limit:{email}` 限制 10 分钟最多 5 次。
4. 验证码保存到 Redis，TTL 为 5 分钟。
5. Spring Mail 通过 QQ 邮箱 SMTP 发送 HTML 邮件。
6. 登录成功后删除验证码，防止重放。

## 4. 注册唯一性

1. 手机、邮箱、用户名先查 Redis Bitmap 布隆过滤器。
2. 布隆判定“可能存在”时再查 MySQL，避免将误判当成真实重复。
3. 用户写入后同步写 `player_profiles`，并把唯一值加入布隆过滤器。
4. MySQL 唯一索引是最终正确性保障，布隆只是读放大优化。

## 5. token 模型

返回给浏览器的 token 是随机字符串，登录态保存在 Redis Hash：

```text
login:token:{token}
  id
  city
  lng
  lat
```

请求使用 `Authorization: Bearer <token>`。token 默认 120 分钟，每次有效请求续期并增加随机抖动，降低同时过期带来的峰值。

## 6. 定位策略

```text
HTTPS 高德 JS API 定位
  -> 失败后 navigator.geolocation
  -> 失败后后端高德 IP 城市级定位
  -> 最后默认西安
```

- 精确定位必须在 HTTPS 安全上下文并由用户授权。
- IP 定位只提供城市或大致范围，不是 GPS。
- 逆地理编码将坐标转成城市和街道文本。
- 登录用户的最新坐标写入 Redis token，请求不再携带长地址参数。

## 7. 数据与关键代码

- MySQL：`users`、`player_profiles`、`follows`。
- Redis：验证码、发送限流、token Hash、布隆过滤器、公开主页缓存。
- 入口：`AuthController`、`AuthService`、`RefreshTokenInterceptor`、`LoginInterceptor`、`BloomFilterService`。

## 8. 安全边界

- 生产环境必须通过环境变量注入 SMTP 授权码和 JWT secret。
- 密码通过 `PasswordService` 哈希后保存，不保存明文。
- 公开主页只返回允许公开的字段。
- Controller 中的 `requireUserId()` 是业务入口二次保护，拦截器则是 HTTP 边界保护。
