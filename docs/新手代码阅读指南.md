# 《约个球》新手代码阅读指南

这份文档假设你刚开始学习 Java、Spring Boot 和 Vue。目标不是让你一次记住所有代码，而是让你知道：

1. 一个功能从页面点击后会经过哪些文件。
2. 每一层负责什么，为什么这样拆分。
3. MySQL、Redis、MinIO、RocketMQ、高德和大模型分别在哪里参与。
4. 遇到看不懂的代码时，应该从哪里继续追踪。

> 最重要的原则：不要从第一个文件开始逐行读完整个项目。以一个用户操作为单位，沿“前端事件 -> API -> Controller -> Service -> Mapper/外部系统 -> 响应”纵向阅读。

## 1. 先建立全局地图

```text
用户点击页面
  -> App.vue 中的事件函数
  -> api('/...')，由 client.ts 统一添加 /api
  -> 开发环境 Vite / 生产环境 Nginx 转发
  -> Spring MVC 拦截器
  -> Controller 接收参数
  -> Service / ServiceImpl 执行业务规则
  -> Mapper 访问 MySQL
     CacheClient 访问 Redis
     MinIOClient 访问 MinIO
     RestClient 访问高德
     RocketMQTemplate 发送消息
     ChatClient 调用 DashScope
  -> ApiResponse 返回 JSON
  -> Vue 更新响应式状态并重新渲染
```

前端和后端通过 HTTP JSON 通信，所以这是一个 B/S 架构项目：浏览器是客户端，Nginx 和 Spring Boot 是服务器端。

## 2. 先认识常见名词

| 名词          | 小白理解                        | 本项目中的例子                            |
| ----------- | --------------------------- | ---------------------------------- |
| Controller  | 接待员，接收 HTTP 请求并把任务交给业务层     | `AuthController`                   |
| Service 接口  | 业务能力清单，说明“能做什么”             | `IAuthService`                     |
| ServiceImpl | 真正的业务流程，说明“怎样做”             | `AuthService`                      |
| Mapper      | 数据库翻译员，把 Java 调用变成 SQL      | `UserMapper`                       |
| Entity      | 与数据库表或领域数据接近的 Java 对象       | `UserAccount`                      |
| DTO         | 请求或服务间传递的数据包                | `LoginRequest`                     |
| VO          | 专门给前端看的返回结构                 | `EquipmentVO`                      |
| Bean        | 由 Spring 创建和管理的对象           | 带 `@Service`、`@Component` 的类       |
| 依赖注入        | Spring 把一个类需要的对象通过构造器传进来    | `AuthController(IAuthService ...)` |
| 事务          | 一组数据库操作要么全部成功，要么全部回滚        | `@Transactional`                   |
| 缓存          | 把常访问结果暂存在 Redis，减少数据库或第三方请求 | `CacheClient`                      |
| 幂等          | 同一请求/消息重复执行也不会产生重复结果        | 秒杀订单唯一索引                           |
| 降级          | 外部组件不可用时采用功能较弱但可运行的路径       | RocketMQ 关闭后同步落库                   |

### 2.1 常见注解怎样看

| 注解                             | 含义                                               |
| ------------------------------ | ------------------------------------------------ |
| `@RestController`              | 这个类提供 HTTP JSON 接口                               |
| `@RequestMapping`              | Controller 的公共 URL 前缀                            |
| `@GetMapping` / `@PostMapping` | GET 查询 / POST 写操作                                |
| `@Service`                     | 这是业务实现类，由 Spring 管理                              |
| `@Component`                   | 通用 Spring 组件                                     |
| `@Configuration`               | Spring 配置类                                       |
| `@Transactional`               | 方法抛出运行时异常时回滚本事务内数据库修改                            |
| `@Valid`                       | 执行 DTO 上的参数校验注解                                  |
| `@MapperScan`                  | 自动发现 Mapper 接口                                   |
| `@Data`                        | Lombok 生成 getter、setter、equals、hashCode、toString |

### 2.2 看到接口和实现类时怎么办

例如 Controller 依赖的是：

```java
private final IAuthService authService;
```

`IAuthService` 只声明方法，真正执行的是带 `@Service` 的 `AuthService implements IAuthService`。在 IDE 中对方法按 `Ctrl+B` 或“转到实现”即可继续。

## 4. 用最简单的查询练习一次

以页面加载运动分类 `GET /api/sports` 为例：

1. 前端 [App.vue](../frontend/src/App.vue) 的 `loadSports()` 调用 `api('/sports')`，请求层统一拼接为 `/api/sports`。
2. [client.ts](../frontend/src/api/client.ts) 加入 Token 请求头并执行 `fetch`。
3. Vite 或 Nginx 去掉 `/api`，后端实际接收 `/sports`。
4. `SportController` 接收 GET 请求并调用 `ISportCatalogService`。
5. `SportCatalogService` 先查 Redis；未命中时返回构造器中注册的稳定运动目录并写入 Redis。
6. `ApiResponse.ok(...)` 统一返回 `{code, message, data}`。
7. Vue 把结果赋给响应式数组，导航栏自动重新渲染。

运动目录目前是代码内的稳定配置，不查询 MySQL。这是最适合第一次阅读的链路，因为它没有
事务、Mapper、消息队列和复杂并发。

## 6. 各业务模块完整流程

### 6.1 启动与请求转发

关键文件：

- [HmBadmintonApplication.java](../backend/src/main/java/com/hm/badminton/HmBadmintonApplication.java)
- [application.yml](../backend/src/main/resources/application.yml)
- [vite.config.ts](../frontend/vite.config.ts)

开发环境中浏览器请求 `/api/auth/me`，Vite 转发到 `localhost:8088/auth/me`。生产环境由 Nginx 完成同样的转发。前端不保存后端真实地址，因此本地和生产代码一致。

Spring Boot 启动时会：

1. 扫描并创建 Controller、Service、配置组件。
2. 创建数据库连接池、Redis、MinIO 等客户端。
3. 执行开发环境 SQL 初始化。
4. 预热布隆过滤器和秒杀 Redis 数据。
5. 注册定时任务、拦截器和 RocketMQ 消费者。
6. 监听 `8088` 接收请求。

### 6.2 登录、注册与 Token

关键文件：

- [AuthController.java](../backend/src/main/java/com/hm/badminton/controller/auth/AuthController.java)
- [AuthService.java](../backend/src/main/java/com/hm/badminton/service/auth/impl/AuthService.java)
- [RefreshTokenInterceptor.java](../backend/src/main/java/com/hm/badminton/interceptor/RefreshTokenInterceptor.java)
- [LoginInterceptor.java](../backend/src/main/java/com/hm/badminton/interceptor/LoginInterceptor.java)
- [UserContext.java](../backend/src/main/java/com/hm/badminton/utils/UserContext.java)

验证码登录流程：

```text
输入邮箱
 -> 校验格式
 -> Redis 检查 60 秒冷却与 10 分钟最多 5 次
 -> 生成 6 位验证码
 -> Redis 保存 5 分钟
 -> QQ SMTP 发邮件
 -> 用户提交邮箱和验证码
 -> Redis 比对
 -> 首次登录自动创建用户和球友资料
 -> 删除验证码
 -> 生成随机 Token
 -> Redis Hash 保存轻量登录上下文
 -> 前端 localStorage 保存 Token
```

为什么注册唯一性既有布隆过滤器又有数据库：布隆过滤器只能说“一定不存在”或“可能存在”，不能精确确认；MySQL 查询和唯一索引才是最终结果。布隆过滤器负责减少大量不存在值的数据库查询。

每次请求的认证顺序：

```text
RefreshTokenInterceptor（所有路径）
 -> 从 Authorization 取 Token
 -> 从 Redis 恢复 userId/位置
 -> 放入 UserContext
 -> 刷新 TTL

LoginInterceptor（仅受保护路径）
 -> UserContext 有用户：放行
 -> 无用户：返回 401

请求结束
 -> UserContext.clear()，防止线程复用串号
```

### 6.3 定位与附近场所

关键文件：

- [amapGeolocation.ts](../frontend/src/api/amapGeolocation.ts)
- [PlaceController.java](../backend/src/main/java/com/hm/badminton/controller/place/PlaceController.java)
- [AmapPlaceService.java](../backend/src/main/java/com/hm/badminton/service/place/impl/AmapPlaceService.java)
- [LocationContextResolver.java](../backend/src/main/java/com/hm/badminton/utils/LocationContextResolver.java)

定位优先级是：HTTPS 浏览器高精度定位 -> 高德 IP 定位 -> 默认西安。HTTP 页面通常无法获得浏览器精确定位，只能走后两级。

附近搜索流程：

1. 前端取得经纬度和运动类型。
2. 后端把经纬度保留约四位小数组成缓存 key。
3. Redis 命中则直接返回。
4. 未命中则调用高德 Web 服务。
5. 结果不够一页时，后端自动按 5km、10km、20km、30km 扩大范围。
6. 以高德 POI id 去重并转换为 `AmapPlace`。
7. 结果短时间写入 Redis，降低第三方调用次数。

这里要区分两个概念：

| 概念 | 来源 | 含义 |
| --- | --- | --- |
| `place` | 高德 API | 真实球馆/场所 POI |
| `venue` | 本地 MySQL | 平台售卖的场馆团购、时段、私教商品 |

### 6.4 场馆团购、装备和普通订单

关键文件：

- `ItemController`
- [VenueItemService.java](../backend/src/main/java/com/hm/badminton/service/trade/impl/VenueItemService.java)
- [EquipmentService.java](../backend/src/main/java/com/hm/badminton/service/trade/impl/EquipmentService.java)
- [TradeOrderService.java](../backend/src/main/java/com/hm/badminton/service/trade/impl/TradeOrderService.java)
- `VenueItemMapper`、`EquipmentMapper`

统一交易类型：

```text
type = 1  场馆商品
type = 2  装备商品
```

场馆商品购买：

```text
选择团购
 -> 选择具体日期/时段 inventory
 -> POST /payments，type=1
 -> TradeOrderService 路由到 VenueItemService
 -> SQL 条件扣 available_stock
 -> 保存场所、商品、日期、时段和价格快照
 -> 模拟支付，更新订单状态
 -> 返回订单和核销码
```

装备购买：

```text
立即购买或购物车结算
 -> POST /payments，type=2
 -> 计算订单总价
 -> 创建装备订单主表
 -> 每件商品用 stock >= quantity 条件扣库存
 -> 保存订单明细快照
 -> 购物车结算时清空购物车
 -> 模拟支付
```

`@Transactional` 放在 Service 层，因为一次购买跨越库存、订单主表、订单明细和购物车。任何一步抛异常，数据库修改整体回滚。

前端 VO 不暴露真实库存数，只暴露 `purchasable` 等用户需要的信息；后端仍在 SQL 中校验库存，不能信任前端按钮状态。

### 6.5 秒杀

关键文件：

- [SeckillService.java](../backend/src/main/java/com/hm/badminton/service/trade/impl/SeckillService.java)
- [seckill.lua](../backend/src/main/resources/lua/seckill.lua)
- [SeckillOrderConsumer.java](../backend/src/main/java/com/hm/badminton/mq/SeckillOrderConsumer.java)
- [SeckillOrderMessageService.java](../backend/src/main/java/com/hm/badminton/mq/SeckillOrderMessageService.java)
- `SeckillMapper`

完整流程：

```text
应用启动
 -> MySQL 秒杀库存和已购用户预热到 Redis

用户抢购
 -> 校验活动时间
 -> 获取 user + type + activity 的 Redisson 锁
 -> Lua 一次性检查库存和一人一单
 -> Lua 扣 Redis 库存并写入已购集合
 -> 生成全局 orderId
 -> 发送 RocketMQ 消息
 -> 立即把 orderId 返回前端

消费者
 -> 反序列化消息
 -> 检查是否已存在订单
 -> MySQL 再次条件扣秒杀库存
 -> 插入秒杀订单
 -> 提交事务
```

为什么同时需要锁、Lua、唯一索引：

| 保护 | 解决的问题 |
| --- | --- |
| Redisson 用户锁 | 同一用户并发连点，减少重复请求进入 Lua |
| Lua | 库存检查、扣减、记录用户在 Redis 内原子执行 |
| MySQL 条件更新 | Redis 与数据库不一致时仍不超卖 |
| MySQL 唯一索引 | MQ 重投或极端竞态时仍保证一人一单 |

RocketMQ 未部署或投递失败时，如果允许同步降级，会直接调用同一个 `SeckillOrderMessageService.createOrder()`，业务规则不会分叉。

### 6.6 社区、关注、点赞与 Feed

关键文件：

- [BlogService.java](../backend/src/main/java/com/hm/badminton/service/community/impl/BlogService.java)
- `FollowService`
- `BlogMapper`、`FollowMapper`
- `BlogMaintenanceTask`

发布动态流程：

1. 博客正文、图片 URL 和关联商品快照写入 MySQL。
2. 博客 id 写入作者的 Redis outbox。
3. 普通作者把博客 id 推到每位粉丝的 inbox。
4. 大 V 不逐个推送，避免粉丝过多导致写扩散。

关注流读取：

1. 从当前用户 inbox 读取普通作者推送。
2. 从关注的大 V outbox 拉取博客。
3. Redis 缺失时从 MySQL 回源。
4. 合并、按 blogId 去重、按时间倒序。
5. 使用 `maxTime + offset` 做滚动分页。
6. 批量补充作者、点赞和关注状态，避免 N+1 查询。

点赞使用 Redis ZSet：member 是 userId，score 是点赞时间。博客表保留总点赞数方便排序。动态删除先软删除，30 天后归档到 `blog_archive`，90 天后再分批物理删除。

### 6.7 球友和约球活动

关键文件：

- [SocialService.java](../backend/src/main/java/com/hm/badminton/service/social/impl/SocialService.java)
- `SocialMapper`
- `VenueActivityBookingService`

发起活动：校验开始时间在未来、结束晚于开始、人数为 2 至 20；随后同一事务写入活动主表和“发起人”成员记录。

加入活动的并发保护：

```text
插入 activity_member
 -> 唯一索引阻止同一用户重复加入
 -> 条件 UPDATE current_players = current_players + 1
    WHERE current_players < max_players AND status = '招募中'
 -> 更新失败则抛异常
 -> 事务回滚刚插入的成员
```

“购买团购并发起约球”是组合业务：前端弹窗让用户确认时段、人数和水平；后端事务完成场馆订单、模拟支付和活动创建。用户仍需主动确认，AI 不会静默下单。

### 6.8 文件与 MinIO

关键文件：

- `FileController`
- [FileStorageService.java](../backend/src/main/java/com/hm/badminton/service/file/impl/FileStorageService.java)
- `FileMetadataMapper`

上传流程：

1. 必须登录，取得 ownerUserId。
2. 校验文件大小、MIME 和后缀。
3. 文件本体上传 MinIO。
4. 读取 ETag，元数据写 MySQL。
5. 若第 4 步失败，主动删除 MinIO 对象作为补偿。

删除文件必须同时满足“已登录”和“metadata.ownerUserId 等于当前用户”。公开图片使用 `/objects/hm-badminton/...` 由 Nginx 直连 MinIO；Java 下载接口主要用于需要下载头或权限控制的文件。

### 6.9 Redis 缓存

关键文件：[CacheClient.java](../backend/src/main/java/com/hm/badminton/utils/CacheClient.java)

| 策略 | 使用场景 | 原理 |
| --- | --- | --- |
| 旁路缓存 | 装备、场馆商品、博客、公开主页详情 | 未命中查库，查不到写短 TTL 空值防穿透 |
| 逻辑过期 | 秒杀活动热点详情 | 过期先返回旧值，抢到锁的线程异步重建 |
| 普通短缓存 | 高德结果、运动目录、球友列表 | TTL 到期回源，增加随机值防同时失效 |

修改数据库后要删除相关缓存，而不是直接赌缓存会很快过期。读代码时看到 `cacheClient.delete(...)`，通常表示前面发生了数据写操作。

### 6.10 AI 助手

关键文件：

- `AgentController`
- [AgentServiceImpl.java](../backend/src/main/java/com/hm/badminton/service/agent/impl/AgentServiceImpl.java)
- `service/agent/tools/`
- `AgentConversationMapper`、`AgentMessageMapper`

一轮对话流程：

```text
收到问题和位置
 -> 用户/IP 限流
 -> 创建或恢复 conversation
 -> 读取 Redis 短期偏好
 -> 保存用户消息到 MySQL
 -> 识别运动、预算、时间和意图
 -> 按需调用真实业务工具
 -> 后端计算候选和推荐分
 -> 只把可解释字段交给模型
 -> DashScope 生成摘要；失败则本地模板降级
 -> 保存答案和卡片到 MySQL
 -> 更新 Redis 会话上下文
 -> 返回答案、卡片和下一步问题
```

这里的关键设计是 grounding：模型只解释后端工具返回的真实场所、商品、库存和活动，不允许自己编造。卡片中的 `action/meta` 供前端跳转，不直接展示给模型和用户。所有购买、加购、加入活动动作都要由前端二次确认。

## 7. MySQL、Redis、MinIO、MQ 分别看什么

| 组件       | 是否事实来源 | 适合保存                      | 不适合保存         |
| -------- | ------ | ------------------------- | ------------- |
| MySQL    | 是      | 用户、商品、订单、活动、博客、关系、文件元数据   | 大文件本体、超高频临时状态 |
| Redis    | 否      | Token、验证码、缓存、秒杀库存、Feed、限流 | 永久订单、唯一事实数据   |
| MinIO    | 文件事实来源 | 头像、博客图、演示素材、附件            | 可查询业务字段       |
| RocketMQ | 传输通道   | 秒杀订单消息                    | 长期业务查询数据      |
|          |        |                           |               |

更详细的 key、表和对象分工见 [数据存储分工-MySQL-Redis-MinIO.md](数据存储分工-MySQL-Redis-MinIO.md)。

## 8. 怎样调试一条请求

以“加入购物车”为例：

1. 浏览器开发者工具 Network 找到请求 URL、方法、请求体和响应。
2. 在 `App.vue` 搜索该 URL，找到发请求的函数。
3. 去 `controller/trade/CartController` 找相同路径注解。
4. 在 Controller 调用的 Service 方法处打断点。
5. 按 F7 进入 Service，观察 userId、type、productId。
6. 继续进入 Mapper，查看最终 SQL 和影响行数。
7. 在 MySQL 查看购物车表，在 Redis 客户端确认是否有相关缓存变化。
8. 如果返回异常，先看 `BusinessException` 的抛出位置，再看 `GlobalExceptionHandler` 如何转换响应。

建议断点位置：Controller 第一行、Service 业务分支、Mapper 调用之后、异常抛出之前。不要一开始就在 getter/setter 中单步。

## 9. 复杂代码的阅读技巧

### 9.1 先看方法输入和输出

例如：

```java
public Long submit(Long userId, Integer type, Long activityId)
```

先翻译成中文：“某用户抢某类型下的某个秒杀活动，成功返回订单号”。有了这句话，再读中间步骤。

### 9.2 把方法拆成阶段

复杂方法已按 `// 1.`、`// 2.` 注释分段。每读完一段，只回答“这一段保护了什么”。例如秒杀：时间保护、重复请求保护、库存原子保护、异步削峰、失败补偿。

### 9.3 分清业务异常和系统异常

- `BusinessException(400/401/404/409...)`：用户输入或业务状态不允许，可直接展示友好提示。
- 数据库连接失败、Redis 超时等：系统故障，应记录日志并视情况降级。

### 9.4 分清应用校验和最终兜底

应用层的 `if (stock <= 0)` 主要用于友好提示；真正防并发超卖的是 SQL 条件更新。布隆过滤器用于加速；真正保证唯一的是 MySQL 唯一索引。

### 9.5 看到事务要检查调用边界

Spring 的 `@Transactional` 通过代理生效。外部 Bean 调用事务方法有效；同一个类内部 `this.method()` 调用可能绕过代理。当前交易编排由不同 Service Bean 相互调用，外层事务可以覆盖内部数据库操作。
