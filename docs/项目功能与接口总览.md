# 项目功能与接口总览

## 访问约定

开发环境：

```text
前端 Vite: http://localhost:5173
后端 Spring Boot: http://localhost:8088
前端请求: /api/xxx
后端实际路径: /xxx
```

Vite 代理负责把 `/api` 转发给后端。生产环境由 Nginx 做同样的 `/api` 反向代理。

后端统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

登录态使用：

```text
Authorization: Bearer <token>
```

## 功能模块

### 1. 用户与认证

功能：

- 邮箱验证码登录/注册。
- 密码登录。
- 获取当前用户资料。
- 更新个人资料与最近定位。
- 查看公开主页。
- Token 刷新拦截器 + 登录拦截器。
- 注册唯一性使用 Redis BloomFilter 预判，再查 MySQL 精准确认。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/auth/register` | 否 | 注册并登录 |
| `POST` | `/auth/code` | 否 | 发送邮箱验证码 |
| `POST` | `/auth/login` | 否 | 验证码登录或密码登录 |
| `GET` | `/auth/me` | 是 | 当前用户资料 |
| `PUT` | `/auth/me` | 是 | 更新用户资料 |
| `GET` | `/auth/users/{id}` | 否 | 用户公开主页 |
| `PUT` | `/auth/location` | 是 | 登录后刷新定位到 token 和 Redis |

关键逻辑：

- 邮箱验证码有冷却和窗口限制：同邮箱 60 秒一次、10 分钟最多 5 次、验证码 5 分钟过期。
- Token TTL 为 2 小时，并加随机抖动，降低大量 token 同时过期的风险。
- `RefreshTokenInterceptor` 尽量拦截所有请求，解析 token 并刷新 Redis 登录态。
- `LoginInterceptor` 只拦截必须登录的接口。

### 2. 运动目录与分类

功能：

- 查询球类列表。
- 查询装备分类或场馆商品分类。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/sports` | 否 | 获取球类：羽毛球、乒乓球、足球、篮球、网球、排球 |
| `GET` | `/categories/{type}` | 否 | `1=场馆商品分类`，`2=装备分类` |

缓存：

- `/sports` 结果适合放 Redis 短缓存，因为内容稳定、访问频繁。

### 3. 高德场所与逆地理编码

功能：

- 根据浏览器定位经纬度查询附近真实场所。
- 逆地理编码，把经纬度转换为城市、区域、简短地址。
- 如果附近结果不足一页，后端自动扩大半径，不让前端循环请求。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/places/nearby` | 否 | 高德附近场所搜索 |
| `GET` | `/places/regeo` | 否 | 经纬度逆地理编码 |

`/places/nearby` 常用参数：

```text
sport=badminton
keyword=羽毛球馆
city=西安
lng=108.94
lat=34.34
radius=5000
page=1
size=20
```

技术细节：

- 后端调用高德 Web 服务 API。
- `AmapPlaceService.nearby` 会按 `5000 -> 10000 -> 20000 -> 30000` 自动扩大范围。
- 多半径结果用高德 POI id 去重。
- 高德无图片时使用本地 MinIO 场馆封面兜底。
- `reverseGeocode` 用经纬度保留 4 位小数作为 Redis key，减少重复调用高德。

### 4. 场馆商品、库存、评价

功能：

- 查询某个真实高德场所挂载的本地团购。
- 查询场馆商品详情。
- 查询未来库存时段。
- 查询场馆评价。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/items/1` | 否 | 查询场馆商品列表或指定场所的商品 |
| `GET` | `/items/1/{id}` | 否 | 场馆商品详情 |
| `GET` | `/items/1/{id}/inventories` | 否 | 场馆商品库存时段 |
| `GET` | `/venues/{id}/reviews` | 否 | 按本地 place id 查评价 |
| `GET` | `/venues/reviews` | 否 | 按城市、球类、场所顺序查评价 |

重要参数：

```text
/items/1?sport=badminton&placeRank=1&limit=6
/items/1?sport=badminton&category=TIME_PACKAGE&page=1&size=12
/venues/reviews?city=西安&sport=badminton&placeRank=1&size=5
```

技术细节：

- 演示数据使用 `city + sport_code + place_rank` 绑定真实高德搜索结果。
- 场馆商品库存不直接暴露给前端做业务判断，前端只展示“可购买/已售罄”。
- 下单时必须绑定 `productId + inventoryId`，保证用户买到具体日期和时间段。
- 商品详情使用 Redis 缓存空值防穿透。

### 5. 装备商城

功能：

- 按球类、分类、关键词查询装备。
- 装备详情。
- 加购物车、直接支付。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/items/2` | 否 | 装备列表 |
| `GET` | `/items/2/{id}` | 否 | 装备详情 |
| `POST` | `/cart` | 是 | 加入购物车 |
| `POST` | `/payments` | 是 | 直接下单并支付 |

技术细节：

- 装备库存扣减使用数据库条件更新：`stock >= quantity`。
- 下单后删除商品详情缓存，避免继续展示旧库存。
- 演示装备描述包含适合人群、优点、缺点，便于 AI 推荐。

### 6. 购物车与普通支付

功能：

- 场馆商品和装备共用统一购物车入口。
- 场馆商品支持加入购物车和直接抢购。
- 装备支持加入购物车和直接购买。
- 购物车支持数量修改和删除。
- 购物车结算只保留一个“结算并支付”动作。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/cart` | 是 | 加购物车，`type=1/2` |
| `GET` | `/cart` | 是 | 查询购物车 |
| `PATCH` | `/cart/{type}/{itemId}` | 是 | 修改数量 |
| `DELETE` | `/cart/{type}/{itemId}` | 是 | 删除购物车项 |
| `POST` | `/payments` | 是 | 直接支付 |
| `POST` | `/payments/cart` | 是 | 购物车结算并支付 |

技术细节：

- 普通支付事务放在 Service 层。
- `TradeOrderService.payDirect` 保证“创建订单 + 支付订单”在同一事务中。
- `TradeOrderService.payCart` 会把场所购物车逐个变成场所订单，把装备购物车合并成一个装备订单。

### 7. 秒杀

功能：

- 场馆商品秒杀。
- 装备秒杀。
- 一人一单。
- 防超卖。
- 异步落库。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/seckill/{type}` | 否 | 查询秒杀活动，`1=场馆商品`，`2=装备` |
| `POST` | `/seckill/{type}/{seckillId}` | 是 | 提交秒杀 |

技术细节：

- 活动详情使用 Redis 逻辑过期，避免热点 key 击穿。
- 启动时将库存和已抢用户集合预热到 Redis。
- Redisson 分布式锁防止同一用户并发重复请求。
- Lua 在 Redis 内原子完成库存预扣和一人一单标记。
- RocketMQ 异步创建订单。
- MQ 投递失败时回滚 Redis 预扣。

### 9. 社区、关注、点赞、Feed

功能：

- 推荐/关注/球类频道博客流。
- 发布动态。
- 删除自己的动态。
- 点赞/取消点赞。
- 关注/取消关注作者。
- 关注流推拉结合。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/blogs` | 否 | 博客列表，支持 `channel/sport/keyword/page/size` |
| `GET` | `/blogs/of/user/{userId}` | 否 | 用户主页动态 |
| `GET` | `/blogs/of/follow` | 是 | 关注流滚动分页 |
| `GET` | `/blogs/{id}` | 否 | 博客详情 |
| `POST` | `/blogs` | 是 | 发布动态 |
| `DELETE` | `/blogs/{id}` | 是 | 删除自己的动态 |
| `PUT` | `/blogs/{id}/like` | 是 | 点赞/取消点赞 |
| `PUT` | `/follows/{id}/{follow}` | 是 | 关注/取关用户 |

Feed 原理：

- 普通作者发布动态时，把博客 id 推到粉丝的 Redis inbox。
- 大 V 不给所有粉丝推送，避免写扩散过大；关注流读取时再拉取大 V outbox。
- `followFeed` 合并 inbox、bigV outbox、数据库兜底结果，去重后按时间倒序返回。
- 滚动分页使用 `maxTime + offset`，解决同一毫秒多条动态重复或漏读的问题。

### 10. 约球与球友

功能：

- 查询同城球友。
- 编辑自己的球友资料。
- 查询约球活动。
- 发起约球。
- 加入约球。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/social/players` | 否 | 球友列表 |
| `GET` | `/social/profile/me` | 是 | 我的球友资料 |
| `POST` | `/social/profile/me` | 是 | 保存球友资料 |
| `GET` | `/social/activities` | 否 | 约球活动列表 |
| `POST` | `/social/activities` | 是 | 发起约球 |
| `POST` | `/social/activities/{id}/join` | 是 | 加入活动 |

技术细节：

- 球友列表可以按城市、球类、水平过滤。
- 活动创建会校验开始时间和结束时间。
- 加入活动用条件更新控制人数，避免并发超员。

### 11. 文件与 MinIO

功能：

- 上传头像、博客图片等文件。
- 查询文件元数据。
- 下载文件。
- 生成预签名 URL。
- 删除自己的文件。

接口：

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/files/upload` | 是 | 上传文件 |
| `GET` | `/files/{id}` | 否 | 文件元数据 |
| `GET` | `/files` | 否 | 文件列表 |
| `GET` | `/files/{id}/download` | 否 | 下载文件 |
| `GET` | `/files/{id}/presigned-url` | 否 | 预签名 URL |
| `DELETE` | `/files/{id}` | 是 | 删除自己的文件 |

技术细节：

- MySQL 存文件元数据。
- MinIO 存文件本体。
- 删除文件时校验所有者。
- 上传失败要考虑 MinIO 成功但 DB 失败的孤儿文件问题。

### 12. AI 助手

功能：

- 支持文字问答。
- 支持底部导航“助手”和全局悬浮 AI 按钮。
- 支持会话保存、历史切换、删除历史。
- 支持快捷问题。
- 快捷问题先选择球类，可不限、单选、多选。
- 返回摘要 + 业务卡片，卡片可跳转场所、团购、装备或活动。

接口：

| 方法       | 路径                                   | 登录  | 说明           |
| -------- | ------------------------------------ | --- | ------------ |
| `GET`    | `/agent/status`                      | 否   | AI 模型是否可用    |
| `POST`   | `/agent/chat`                        | 否   | 发送问题，返回答案和卡片 |
| `GET`    | `/agent/conversations`               | 是   | 聊天历史         |
| `GET`    | `/agent/conversations/{id}/messages` | 是   | 历史消息         |
| `DELETE` | `/agent/conversations/{id}`          | 是   | 删除历史会话       |

技术细节：

- 框架：Spring AI Alibaba + DashScope。
- 模型：默认 `qwen-plus`。
- 工具：场所、场馆商品、约球活动、装备、用户偏好。
- 限流：登录用户按 userId，游客按 IP。
- 模型不可用时，仍返回本地候选卡片和兜底摘要。

## 重要技术点总结

| 技术点 | 当前实现 |
| --- | --- |
| 分层结构 | Controller / Service / Mapper / Entity / DTO / VO |
| ORM | MyBatis-Plus + Mapper XML/注解混合 |
| 缓存穿透 | Redis 空值缓存 |
| 缓存雪崩 | TTL 加随机抖动 |
| 缓存击穿 | 秒杀活动详情使用逻辑过期 |
| 秒杀防超卖 | Redis Lua 原子扣减 |
| 秒杀一人一单 | Redisson 用户锁 + Redis Set + DB 唯一约束 |
| 秒杀异步落库 | RocketMQ |
| 文件存储 | MySQL 元数据 + MinIO 文件本体 |
| 地图能力 | 高德 Web 服务 API + 浏览器定位 |
| AI | Spring AI Alibaba + DashScope + 工具调用候选数据 |
